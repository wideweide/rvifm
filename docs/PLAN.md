# PLAN — rvifm 里程碑计划

本文件只回答“分几阶段、每阶段目标、依赖关系、何时发布”。单次提交粒度的任务见 [TASKS.md](TASKS.md)，验收标准见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 1. 总体策略

- 采用 **harness 模式**：文档是契约，Agent 每轮只做一个小任务，更新状态并提交。
- **M0–M6 构成 v0.1.0 核心版本**：可日常使用的浏览、文件操作、撤销、选择、搜索、配置、帮助。
- **M7–M11 是 v0.1.0 之后的增强**：归档浏览、frecency、图标主题、声明式键位、预览与打开。
- 优先级：`M0–M2` 必须闭环，尤其是 `u` 撤销；M3–M11 可以简化，但不得跳过文档更新。
- 每个阶段结束必须产出可运行版本、通过质量门禁、更新 `PLAN.md` 状态。

## 3. 阶段依赖说明

- **M1 必须包含多标签**：每个 tab 持有独立的 `Location`、光标、滚动、搜索状态。晚加会导致 M2 撤销、M4 搜索、M7 归档浏览全部回头改“当前 tab 上下文”。
- **M2 必须在 M1 之后**：撤销栈依赖稳定的 `Tab` / `AppState` 结构；撤销栈全局共享，`UndoableOp` 记录 tab 标识。
- **M3 依赖 M2**：批量操作复用单文件操作与撤销逻辑；tag 状态在批量操作后清空。
- **M4 依赖 M1**：搜索/过滤作用于当前视图；路径跳转由 M8 的 `pick` 覆盖，marks 由 frecency 实现并持久化（M25-2）。
- **M5 依赖 M1–M4**：配置与最小命令模式建立在已稳定的导航、操作、搜索之上；键位覆盖推迟到 M10。
- **M6 依赖 M0–M5**：发布门禁需要完整核心功能与双平台 CI。
- **M7 依赖 M1、M4**：归档导航复用 `Location` 与搜索链路；不依赖配置系统。
- **M8 依赖 M1、M7**：`pick` / TUI 共用导航与预览；预览抽象在 M8 抽出，M11 扩展图片/Office/PDF。
- **M9 依赖 M1、M7、M8**：文件列表、归档浏览、pick 预览共享同一套图标/主题渲染。
- **M10 依赖 M1–M5**：动作层覆盖导航、文件操作、选择、搜索、命令模式。
- **M11 依赖 M7–M10**：预览覆盖物理目录、归档、pick；opener 分层与 M10 键位分层同构。
- **M12 依赖 M2**：提权作用于具体写操作，不提升主进程；取消后状态必须与操作前一致。
- **M13–M14 依赖 M6–M11**：对齐增强与双栏模型建立在稳定核心与预览栈之上。
- **M15–M18 依赖 M14**：实测反馈、导航、搜索查看器与排序都作用于双栏模型。
- **M19–M20 依赖 M15–M18**：远端 VFS 先浏览配置，再写操作与跨 VFS；SFTP 口令/known_hosts 安全边界在 M22 补齐。
- **M21–M23 依赖 M19–M20**：UI/UX 打磨与 frecency 对齐以完整 VFS 能力为基线。
- **M24–M25 依赖 M23**：交互增强、会话/归档创建/git 集成复用既有 TUI、frecency 与 keymap 基建；M25-2 marks 与 bookmark 共用 frecency 存储。
- **M26 依赖 M7、M24-9、M25-3/4**：扩展归档写端需复用只读 VFS、Job 取消模型和既有 `:archive`/校验链路。
- **M27-1 依赖 M1/M2**：符号链接目录复用 `Location`/`navigate_to` 与文件列表分类；不依赖 AUDIT。
- **M27-2 依赖 M9/M14 与 AUDIT-13**：vifm 风格配色复用主题接线；主题未接通时使用 16 色回退，避免再次形成“有样式无加载”。
- **M27-3 依赖 M11 与 AUDIT-2**：AUDIT-2 先接通第 1 页最小视觉链，M27-3 再扩展 1–2 页与 `[preview]` 配置。
- **AUDIT 无前置依赖**：整改项按 P0 → P1 排序，建议先解除 `pick` 只读红线，再处理 CI 增强项。
- **M27 状态**：用户 2026-11-19 确认撤销「暂不启动」，按 TASKS 顺序排队（AUDIT → M25-2 → M26 → M27）；M27-2/3 仍排在 AUDIT-13/2 之后。

## 4. 发布划分

### v0.1.0（M0–M6）

交付标准：

- 能完成日常浏览、多标签、选择、复制、移动、删除、重命名。
- `u` 撤销可用，覆盖核心可逆操作，跨 tab 正确回滚。
- 有基础搜索、tag 批量操作、TOML 配置、最小命令模式、帮助页。
- 代码结构清晰，`cargo fmt` / `clippy -D warnings` / `build` / `test` 通过。
- CI 在 Linux + Windows 全绿，Release 产出两端可执行文件。
- README 明确声明“参考 vifm，非严格兼容”。

### v0.2.0–v0.8.0（M7–M23，已发布）

- M7 归档浏览、M8 frecency、M9 图标主题、M10 声明式键位、M11 预览与打开 → 0.2.0。
- M12 提权、M13–M14 vifm 对齐与双栏 → 0.4.0 / 0.5.0；M15–M17 → 0.6.0；M21 → 0.7.0；M22–M23 → 0.8.0。
- 每个里程碑独立可发布；M19–M20 随后续 minor 版本交付。

### 待发布（M24 / M25 / M26 / M27 / AUDIT）

- 所有任务（M24 / M25 / M26 / M27 / AUDIT / M25-2 重定义）统一随任务列表全部完成后发布 **0.9.0**，不再按批次拆分版本。
- **自动发布规则**：任务列表（`TASKS.md`）全部执行完成（所有非 OUT_OF_SCOPE 任务勾选或明确 deferred）后，自动执行发布流程——跑完整阶段验收 + 双平台 CI 全绿 + 版本 bump + crates.io + tag/GitHub Release；不再等待人工发布决策。发布失败按“无法继续的异常”暂停并报告。

## 5. 执行约束与风险

### 上下文控制

取消 token 预算估算（已不适用）。控制手段保留：

- 每轮只注入当前任务相关 SPEC 片段，不通读全文。
- 每轮只做一个任务，避免上下文膨胀和半成品堆积。
- 同一任务 3 轮不过验收就缩小范围并 `deferred`。
- 一轮结束自动进入下一轮（见 AGENTS §3 自动续轮），无需人工确认。

### 主要风险

| 风险 | 缓解 |
|---|---|
| `u` 撤销的跨 tab、不可逆边界复杂 | M2 单独验收，删除走可恢复路径，必要时缩小到核心可逆操作 |
| 归档格式边界多（损坏、加密、超大索引） | 先支持 zip/tar/tar.gz，7z/rar 明确不支持；错误处理纳入验收 |
| `redb` 多进程并发 | 短事务 + 重试 + `events.pending` 降级；评分只在读时重放 |
| pending 合并破坏 `pick` 只读红线（本次评估发现） | 移出 `pick` 路径或提供只读 open；AUDIT-1，决策入 NOTES §8 |
| 图片协议碎片化 | `ratatui-image` 探测 + halfblocks 无条件兜底，不为终端写分支 |
| `exprim =0.4.0` 供应链风险 | 仅作非默认 `pdf-visual` feature；固定 `=0.4.0` + `Cargo.lock` 入库；按 NOTES.md §4.8 复评 |
| 文档与实现漂移（本次评估发现） | 以 `SPEC` / `STATE` 为单一事实源，AUDIT 批次整改；`REVIEW.md` 记录结论 |
| `app.rs` 上帝文件（15k 行） | AUDIT-5 按职责拆分，测试随迁 |
| 主题/opener 整层未接线（第二轮复核发现） | AUDIT-13 / AUDIT-7：接入生产路径后再关闭对应阶段 |
| 测试受宿主 `TMUX`/`STY` 影响（第二轮复核发现） | AUDIT-14：隔离环境变量，CI 与本地均需稳定 |
| 符号链接目录被误判为文件（0.8.0 实测） | M27-1：分类跟随目标、`l`/Enter 内部导航、断链可读 |
| vifm 风格配色改动导致列表/预览回归 | M27-2：TestBackend 快照 + `pane_borders=true` 保留旧外观 |
